# Architecture

## Generation flow

```text
DOCX upload + Elementor JSON template
                 │
                 ▼
         Background job queue
                 │
                 ▼
          WP-Cron worker
          ├── Read DOCX
          ├── Decode Elementor JSON
          ├── Map marked content and repeat regions
          ├── Apply image and phone-link options
          └── Create/update the WordPress page
                 │
                 ▼
       Save Elementor data and rebuild CSS
```

Template validation uses the same DOCX reader, template decoder, and mapping rules, but does not create a page.

## Components

- `wolf-forge-elementor-page-generator.php` loads the classes, registers the queue schedule, and scopes frontend CSS to plugin-generated pages.
- `WFEBPG_DOCX_Reader` extracts paragraphs, heading levels, and legacy repeat metadata from DOCX files.
- `WFEBPG_Template` decodes Elementor JSON and normalizes custom markers, including legacy spellings.
- `WFEBPG_Generator` maps content, expands repeat regions, creates pages, handles the queue, and validates templates.
- `WFEBPG_Phone_Linker` converts supported US phone numbers in text to `tel:` links without rewriting existing links or HTML attributes.
- `WFEBPG_Logger` stores the rolling activity and error log.
- `admin/admin-page.php` provides the dashboard, template library, validator, image tools, and WordPress/AJAX handlers.
- `assets/admin.js` and `assets/admin.css` implement the dashboard interactions and layout. `assets/frontend.css` adjusts layout only on pages generated by the plugin.

## Queue behavior

Jobs are stored in the `wfebpg_queue` WordPress option. A lock prevents overlapping workers. Each worker processes a bounded batch with a time limit; a queued job also schedules a near-immediate cron event. WP-Cron must be triggered by site traffic or a server cron.

## Marker and storage compatibility

The generator populates only marked elements. Structural `data-customID|repeat` markers identify whole Elementor items; heading/widget repeat markers and legacy marker forms remain supported.

The `WFEBPG` prefix is part of the stored-data and WordPress integration contract. Options, user metadata, AJAX actions, cron hooks, generated-page metadata, PHP class names, and CSS selectors retain their existing names to avoid a data migration.
