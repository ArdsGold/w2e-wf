# Architecture

## Design goal

The plugin is a small WordPress application that converts structured DOCX content into Elementor page JSON and then creates WordPress pages from that JSON.

The architecture deliberately keeps the existing WFEBPG internal identifiers for compatibility.

## Components

### `wolf-forge-elementor-page-generator.php`

Bootstrap file.

Responsibilities:

- registers the plugin metadata;
- defines shared paths and version constants;
- loads the internal classes;
- registers queue activation/deactivation behavior;
- hooks the queue worker into WP-Cron;
- adds generated-page body classes;
- enqueues generated-page CSS.

### `includes/class-docx-reader.php`

DOCX parser.

Responsibilities include extracting:

- headings;
- paragraphs;
- heading levels;
- yellow repeatable-heading information;
- semantic non-repeat blocks;
- content needed by the generator.

### `includes/class-template.php`

Elementor JSON helper.

Responsibilities:

- decode supported Elementor JSON shapes;
- encode generated element arrays;
- read page settings;
- extract custom marker IDs from Elementor settings.

### `includes/class-generator.php`

Core generation engine.

Responsibilities include:

- mapping DOCX blocks to Elementor markers;
- populating non-repeat content;
- expanding repeatable sections;
- cloning Elementor structures;
- handling repeatable images;
- preserving alternating card colors;
- generating WordPress pages;
- queue processing;
- template validation;
- static image replacement support.

This file is intentionally kept as the central engine because splitting it aggressively would create a larger compatibility surface for a rebrand release.

### `includes/class-phone-linker.php`

Handles supported phone-number-to-`tel:` conversion.

### `includes/class-logger.php`

Provides lightweight plugin logging through WordPress options.

### `admin/admin-page.php`

Contains the admin interface, form handling, template library UI, validation UI, generated-page management, and queue controls.

### `assets/admin.js`

Handles browser-side admin interactions such as:

- Media Library image selection;
- saved template uploads;
- DOCX upload progress;
- queueing interactions;
- preview helpers.

### `assets/frontend.css`

Frontend CSS used only on pages marked as generated by the plugin.

## Generation flow

```text
DOCX + Elementor JSON
        │
        ▼
   DOCX Reader
        │
        ▼
Semantic document blocks
        │
        ├──────────────┐
        ▼              ▼
Non-repeat mapping   Repeatable mapping
        │              │
        └──────┬───────┘
               ▼
       Elementor element tree
               │
               ▼
       Template adjustments
               │
               ▼
       WordPress page creation
               │
               ▼
       Generated-page tracking
```

## Queue flow

```text
Admin submission
      │
      ▼
WordPress option-backed queue
      │
      ├── single event (~5 seconds)
      │
      └── recurring minute worker
                 │
                 ▼
          worker lock acquired
                 │
                 ▼
          generate small batch
                 │
                 ▼
          update queue state
                 │
                 ▼
          release worker lock
```

The lock and time guard are important because Elementor page generation can be resource-intensive.

## Compatibility identifiers

The following are intentionally stable across the r2.x releases:

- `WFEBPG_*` PHP constants/classes/functions;
- `wfebpg_*` WordPress hooks and AJAX actions;
- `wfebpg_queue` and related stored options;
- `_wfebpg_generated` post meta;
- existing saved-template paths and job data.

The product-facing name changes, but the persisted implementation identifiers do not.
