# Architecture

## Generation flow

```text
DOCX upload + Elementor JSON template
                 │
                 ▼
         Background job queue
                 │
                 ▼
          WP-Cron worker
          ├── Read DOCX
          ├── Decode Elementor JSON
          ├── Map marked content and repeat regions
          ├── Apply image and phone-link options
          └── Create/update the WordPress page
                 │
                 ▼
       Save Elementor data and rebuild CSS
```

Template validation uses the same DOCX reader, template decoder, and mapping rules, but does not create a page.

## Components

- `wolf-forge-elementor-page-generator.php` loads the classes, registers the queue schedule, and scopes frontend CSS to plugin-generated pages.
- `WFEBPG_DOCX_Reader` extracts paragraphs, heading levels, and legacy repeat metadata from DOCX files.
- `WFEBPG_Template` decodes Elementor JSON and normalizes custom markers, including legacy spellings.
- `WFEBPG_Generator` maps content, expands repeat regions, creates pages, handles the queue, and validates templates.
- `WFEBPG_Phone_Linker` converts supported US phone numbers in text to `tel:` links without rewriting existing links or HTML attributes.
- `WFEBPG_Logger` stores the rolling activity and error log.
- `admin/admin-page.php` provides the dashboard, template library, validator, image tools, and WordPress/AJAX handlers.
- `assets/admin.js` and `assets/admin.css` implement the dashboard interactions and layout. `assets/frontend.css` adjusts layout only on pages generated by the plugin.

## Queue behavior

Jobs are stored in the `wfebpg_queue` WordPress option. A lock prevents overlapping workers. Each worker processes a bounded batch with a time limit; a queued job also schedules a near-immediate cron event. WP-Cron must be triggered by site traffic or a server cron.

The dashboard's **Process All Queue Now** button sends sequential nonce- and capability-protected AJAX requests to the same bounded worker. Each result returns processed, failed, remaining, and busy values. The browser continues until the queue is empty and no worker is busy, waiting between requests when another worker holds the lock. Request failures end the loop with a retry message. The worker rereads the queue after each job so jobs enqueued during generation are retained. This manual loop requires the dashboard to remain open and does not replace WP-Cron.

**Cancel Queue** clears the waiting queue through a separate protected AJAX endpoint without removing the active worker's lock or interrupting generation. The worker clears its local queue-option cache before rereading between jobs. The dashboard stops timers and uses a run identifier to ignore responses belonging to the cancelled loop. Cancellation removes queue entries only; generated pages, templates, and upload files are retained.

## Marker and storage compatibility

The generator populates only marked elements. Structural `data-customID|repeat` markers identify whole Elementor items; heading/widget repeat markers and legacy marker forms remain supported.

Repeat-column layout stores the rounded integer percentage in `_column_size`, which becomes an Elementor CSS class, and the exact percentage in `_inline_size`, which generates the custom width rule. Fractional values must not be stored in `_column_size`. Both structural rows and legacy centered partial rows follow this contract.

Scope-sensitive traversals share `mapping_child_keys()`: within a Section/Container with one marked H1/H2 branch, that branch is visited first. The saved element arrays keep their original order. The rule applies to content mapping, repeat collections, internal FAQs, inline streams, structural location lookup, and Validator traces. Internal FAQ population runs independently of external card collections. Structural regions expand in reverse scope order to avoid renumbering later collections; remaining widget collections are populated afterward.

The `WFEBPG` prefix is part of the stored-data and WordPress integration contract. Options, user metadata, AJAX actions, cron hooks, generated-page metadata, PHP class names, and CSS selectors retain their existing names to avoid a data migration.

## Shared dashboard settings (r2.2.2)

`includes/admin-settings.php` reads shared `wfebpg_*` WordPress options, seeds missing preferences from the first visiting administrator's existing user metadata, and validates autosave patches. `wfebpg_save_settings` requires `manage_options` and a valid AJAX nonce; its allowlist covers repeat settings, parent page, overwrite, image-pool enablement, active tab, and log filters. Existing template, image-pool, image-map, and fallback endpoints now read/write shared options too. Unrelated settings are not overwritten by a patch.

The JavaScript autosave queue serializes dashboard patches, shows save status, and retains failed changes for retry. Active tabs use saved server state instead of sessionStorage. The image-pool toggle is restored independently of selected image IDs. Temporary previews and notification acknowledgments continue using user metadata.

Queued jobs capture their generation settings at submission, including `widgets_no_limit`; later dashboard edits do not alter queued jobs. Unlimited generation uses the scoped item count as the section capacity in the structural path and disables splitting per collection in the widget path.

## Matching-title page links

`includes/class-title-linker.php` resolves the `link` marker/flag after content mapping and post creation, before Elementor data is saved. It uses native widget URL controls and searches only the current site's published page titles. It reads IDs/titles without loading all page content, compares normalized visible text with Unicode-aware case-insensitive equality, excludes the source page, and keeps manual/dynamic URLs intact.

Unresolved sources carry `_wfebpg_title_links_pending` post metadata. Every completed generation retries those published source pages using their current `_elementor_data`. Successful changes invalidate `_elementor_element_cache`, clear the post cache, and regenerate the affected page's Elementor CSS. Pending sources survive separate worker requests.

`_wfebpg_title_link_targets` stores target ID, last generated URL, and source title, keyed by widget ID/link field or Icon List item ID. Refresh changes a URL only while it still equals the last generated value. Dynamic links, manual overrides, and removed markers release ownership. Regeneration clears old tracking before processing fresh template data. `wp_after_insert_post` and `deleted_post` coalesce slug/parent/status changes and deletions into one shutdown refresh of all tracked source pages, including links to descendants. Nonpublished targets retain their ID with a blank URL. The nonce-protected administrator refresh action queries pages with `_elementor_data`, including manually created pages, fills blank marked links, and adopts verified legacy title/permalink pairs. Automatic refreshes query `_wfebpg_title_link_targets` instead, so tracked manual pages follow future target moves too. Unchanged Elementor arrays are not re-encoded, and manual pages never receive `_wfebpg_generated`; uncertain URLs remain untouched and logged. `tests/title-link-refresh.php` covers stable targets, hierarchy changes, overrides, publication changes, legacy adoption, and hook coalescing.

Run `php tests/title-linker.php` to verify matching boundaries, native fields, repeated markers, validation, and forward references across worker batches using WordPress/HTTP-free stubs.

## Elementor Free marker inputs

`includes/elementor-markers.php` uses Elementor core's `elementor/element/after_section_end` hook to add a text control (`wfebpg_marker`) in an Advanced > Wolf Forge section after the native advanced layout controls. It supports widget common controls plus container, section, and column stacks, without Pro APIs. Elementor persists the setting in the exported element data.

`WFEBPG_Template` gives a nonblank dedicated setting priority over legacy marker attributes, then reads recognized `wf-` tokens from widget `_css_classes` or structural `css_classes`. Heading/content tokens take precedence over modifiers regardless of CSS class order. All sources feed the existing marker normalization; generation, validation, previews, and title matching therefore share the behavior. `clear_marker()` removes consumed inline-repeat markers from every source without discarding unrelated attributes or styling classes.

Verification: `php tests/marker-inputs.php`, plus `php tests/title-linker.php field` and `php tests/title-linker.php css` for native widget fields and forward references across queue batches.

## Container rows and Nested Accordion

Structural repeats prefer the existing legacy Section row owner; pure-Container documents fall back to the nearest containing Container outside the marked card itself. Rebuilding that row preserves native container styling while applying collection capacity. Nested Accordion is classified as an internal repeater, so its FAQ records are excluded from external card collections. Its `items` hold question titles; cloned child containers hold the paired answer Text Editors.

Runtime validation checks the availability of native Container and Nested Accordion types through Elementor's managers. Generation performs the same preflight before creating/updating a WordPress page. This prevents disabled Elementor features from producing a misleading successful, empty page. `tests/container-and-nested-accordion.php` covers mixed service/FAQ scopes and accepts optional real template/DOCX paths.

## Native telephone-link preservation

Before processing an element's string settings, the generator asks `WFEBPG_Phone_Linker::preserve_widget()`. Native URL controls containing `tel:` trigger a skip for Button widgets. Other widgets are skipped only when a supported number in their text normalizes to the same destination. Native URL strings are excluded from HTML conversion, and existing HTML anchors remain protected by the original text-node linker. Child elements are evaluated independently. `tests/phone-widget-preservation.php` covers native fields, matching/nonmatching numbers, extensions, button behavior, mixed linked/unlinked text, and recursion.
